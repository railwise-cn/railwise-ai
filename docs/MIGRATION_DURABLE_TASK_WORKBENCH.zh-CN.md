# 持续任务与文档交付工作台迁移说明

本版本在现有 KUN 运行时上增加持续任务、任务工作台、持久待办和工程文档交付模板。旧聊天、写作、Flow、工作区和插件入口继续可用。

## 数据变化

- `tasks.sqlite3` 增加任务输入、人工待办、操作回执和 outbox 表。迁移前会在同一数据目录保留 `tasks.sqlite3.pre-durable-v1.bak` 备份。
- `flow.sqlite` 增加操作回执和 outbox 表；已有数据库迁移前会保留 `flow.sqlite.before-delivery-v1.sqlite` 备份。现有 Flow 定义、运行记录和历史不删除。
- 来源事件迁移使用 `flow.sqlite.before-source-inbox-v2.sqlite` 一致性备份，增加来源收件箱、nonce 和固定版本派发。Schedule 已接收事件与下次时间一起保存；不会因恢复补跑无限历史周期。
- 文档候选保存到工作区 `.workwise/delivery-candidates/<taskId>/`，并使用旁置的 `.sources.json` 保存来源。候选不会覆盖原 Markdown。
- DOCX/PDF/HTML 交付副本保存到 `.workwise/delivery-exports/<taskId>/`。每个格式单独保存结果、大小和哈希；失败不会删除已生成草稿或冒充完整交付。

## 兼容性

旧 `activeFilePath`、任务 IPC、插件、MCP、Skill、凭据引用和用户文件继续读取。旧任务恢复时沿用原任务记录；终态任务重试会生成关联的新执行记录，不覆盖旧失败证据。

## 用户可见行为

任务输入先保存再执行，重复提交相同幂等键不会重复处理。暂停会停止新的派发，取消会保留已生成成果。审批和问题在重启后仍显示在“需要你”中；运行时重启后，已回答的问题由持久 outbox 创建 continuation turn，不依赖内存 Promise。外部操作已执行但回执未落盘时会标记为“结果待核实”，不会盲目重放。任务模板包括监测报告、招投标技术文件以及通用研究与文档，均先生成可审阅 Markdown 候选。

独立 Flow 的审批与断点也进入任务待办，按工作区筛选，仍由原 Flow 的审批/继续操作处理。取消等待中的 Flow 会保存取消状态；较旧的事件不会重新打开已处理事项。

新建内置交付模板仅获得资料读取、候选生成、确定性监测分析和受限文档导出能力，不自动继承所有已安装工具。旧用户 profile 不会批量改写，插件、MCP 和 Skill 不删除。需要 Shell、其他工具或外部来源的用户任务仍使用原普通任务入口及现有授权。

来源记录保存读取当时的实际文件哈希。目录列表不等于读过内容；来源在模型读取后发生变化，会提示重新读取，并阻止把旧证据生成的候选作为当前内容提交。候选接受前再次校验目标文件版本；原内容和竞争版本保留供处理。导出重试核验原产物或查询回执，不会覆盖用户文件。

新候选可记录来源对应的章节。旧候选没有章节映射时按全部章节受影响处理，不会丢弃旧来源。局部重生成以原候选哈希为基线，保留未选章节与原目标基线，生成新文件和新版本，不覆盖旧候选；重名标题使用 section ID。局部修订保留原标题及子标题结构，标题结构重排仍需生成新整篇候选后审阅。

任务结束后可建立新任务继续局部修订，旧候选和旧任务保留。新任务仅能引用当前授权工作区内的精确候选；新文件与必要图片副本写入新任务目录，对应相对目录保持一致，不修改旧任务文件。

子 Agent 的会话、检查点和交接文件保存在应用数据目录。恢复时会继承父任务的工作区、工具和预算交集；发现未完成的工具调用时进入结果待核实状态。长期记忆默认只召回已接受事实，经验候选需要显式启用并接受；缺少项目归属的历史记忆会保留为“待关联”，不会跨项目注入。

子任务原先可在继承父工具权限后直接调用 Shell 或修改工作区文件，提示词中的暂存目录并不能提供写入隔离。本版将子任务执行权限进一步收紧为已授权资料读取和受限候选工具：通用 `write`、`edit`、`bash` 及任意 MCP/外部动作在实际执行边界拒绝；候选、导出和确定性分析仍受父授权约束，并由各自工具限定输出位置。子任务暂存目录为工作区 `.workwise/task-staging/<childId>`，Markdown 候选继续保存在各子任务自己的 `.workwise/delivery-candidates/<taskId>`，最终接受与写入由父任务的审阅服务完成。父任务已有工具权限不变。旧应用数据中的 staging、子会话、工具结果和用户文件全部保留；恢复不会重新执行已有副作用。需要任意命令或正文修改的子任务应将要求交回父任务，由父任务在已有授权内执行，不要求用户重新配置插件。

主任务和子任务在实际模型执行时共享模型与 Worker 容量，等待人工回答或工具时释放执行名额；子任务数量和并发上限继续保留，暂停或等待不会放宽这些限制。

## 回退与清理

新任务能力可以不使用，原聊天和写作入口继续工作。不要手动删除新增表或 `.workwise/delivery-candidates`；需要恢复时应使用应用提供的历史/候选操作，以保留来源和审阅记录。

需要临时关闭自动任务调度时，可在启动 Runtime 的环境中设置 `RAILWISE_TASK_SCHEDULING_DISABLED=1`。该选项停止启动恢复、Watchdog 自动接管、子任务恢复、Schedule/来源事件后台派发及交付协调器；已接收事件和 outbox 保留等待后续启用，任务和成果仍可查询，普通聊天与用户显式执行入口继续可用。它不关闭租约续期、fencing、回执或权限检查，也不修改保存的用户调度配置。移除该环境变量并重启后恢复正常后台调度。
