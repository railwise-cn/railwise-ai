## 合并后的最小顺序

### A. 空状态、身份、导航和品牌（一次）

1. 从新隔离环境启动冻结包，记录默认主题、语言、模型、版本和启动时间。检查启动、产品/工具菜单、设置、关于、内业标题、OAuth 回调显示品牌和候选身份；仅技术兼容标识允许 WorkWise。
2. 内业首屏保持“概览 / 处理 / 结果 / 交付”四区域，摘要三项，一个清晰主动作；AI 对话可关闭/恢复，工作面不透明、可扫描。检查无资料/无结果/无交付状态、图标回退与 tooltip/aria-label。
3. 新建任务名称可选，上传资料或描述目标进入统一处理入口。进入经典手动路径仍可操作；旧 tab 深链落到有效新页面，高级能力保留。选编程/内业/Write/Design/Flow 后各会话隔离且草稿保留。
4. 新建第二个隔离项目用于后续 scope 检查：切换期间清空前项目结果，等待返回不得覆盖当前项目或对话。

### B. IN2 与 GSI：两条专业主链（各一次）

**B1 IN2 输入：** `kun/src/engineering/fixtures/survey-formats/cosa-in2/golden-plane-control-e2e.in2`。来源为公开合成样例，不是现场工程。按实际允许条件确认平面基准/单位、已知点与角色；“待确认”不能被 AI 描述为已落实工程基准。

**B2 GSI 输入：** `kun/src/engineering/fixtures/survey-formats/professional/leica-gsi-cumulative-leveling.gsi`；起算点 `BM,100.000`。先不填起算点触发阻断，再用修复按钮聚焦输入、填入后重新导入同一原件。

对两条链共同执行：

1. 统一“上传资料”入口 → 自动预检。核对原件名称、点/站/观测数量、单位、已知点、源行定位和来源条件。默认仅专业内容；不展示 parser、P0/P1、内部对象 ID、枚举、工具名、参数 JSON 或散列。高级追溯仍可展开。
2. GSI 缺起算点时全部阻断原因可见、可计算状态为阻断、开始计算禁用，不同时显示“资料通过”。COSA 畸形 DMS/后视缺失各选一个负样例检查专业错误和直接修复动作；不错误放行。
3. 在最终允许状态点击一次明确的开始计算。结果为“候选/待审查”，不自动升级审查、规范合格或签认。查看残差、精度、点位及原件定位；单次坐标改正不叫位移、不可用高程改正不写为 0。
4. IN2 独立核对 S1 最终坐标、初始坐标及改正数口径；误差椭圆长/短轴和协方差单位、方向角约定正确。后验残差范数不称平差前闭合差；未实施独立闭合检查明确未评估。
5. GSI 核对路线闭合 0.4 mm、未知高程及后验精度；未配置闭合限差只能未评估，不能“合格”。独立分数核算作为数值复核，不能升级现场精度或厂商认证。
6. 生成审查稿 → 文件/关键警告 → 原生 DOCX、PDF、XLSX 各一次。普通交付不列 `professional-review.json`；普通报告不泄漏技术附录。读回三个格式，核对同源数值、单位、警告、审查状态；PDF 检查所有页面分页与表格，尤其孤立标题和末页。
7. 高级区域打开来源及审查记录，确认可追溯且保留不可覆盖的记录/修订链；五项技术核验与真实专业签认分开。结果证据定位一次即可供后续问答复用。

### C. 监测 CSV / XLSX（各一次，复用三导出）

1. 使用新生成且显式标记“合成验收”的同源 CSV/XLSX，输入、字段、单位、时间和预期趋势冻结并记 SHA-256。两种格式都走统一上传入口；自动监测识别和显式测量表格选择不会互相混淆。
2. 导入/字段映射 → 预检问题 → 确认 → 分析 → 结果趋势 → 审查稿；记录主动作数量和首次结果时间，只叫验收测量，不称真实工程生产 KPI。
3. 选 CSV 或 XLSX 其中一条完整原生 DOCX/PDF/XLSX 与审查记录导出；另一条核对相同确定性结果并至少保留一次实际审查稿生成。若任务要求逐格式三导出，分别执行，不能用第一条替代。
4. 来源重放、过期/缺原件历史记录、导出取消和重试；保留历史状态。证据问题按钮准备草稿但不自动发送，不覆盖已有正文/附件。

### D. 真实模型、修改/执行审批和恢复（一次正常链 + 每种恢复一次）

1. 新任务确认默认 `deepseek-flash`；真实无提示修复的 GSI 规划，简短“目标 / 输入 / 预计结果 / 风险”卡片，一次“确认并运行”后执行。记录实际发送的 provider/model/effort 和持久事件；仅下拉显示不是实际模型身份的充分证据。
2. 显式选 `deepseek-v4-pro`，对 IN2 S1 和 A 精确问题各一次，保留原问题和读取记录。答复只给测量结论、依据、单位和复核意见；不用工具/哈希/内部状态解释读取过程；A 固定基准不被描述为受本网独立检核或有后验点位精度。
3. 点击结果问题先准备精确引用 → 关闭/恢复草稿 → 明确发送 → 读取正确行 → 返回原件/观测/结果定位；已过期/错项目引用必须拒绝，不能替换为最新相似记录。
4. 普通咨询不产生计算或修改；修改建议展示前后值，一次确认后生效。方案修订、上下文变化后旧批准失效，重新规划需新确认。
5. 原无效草稿只读恢复，修复请求需要明确发送，真实模型更正草稿后批准执行；原无效记录保留。若无法自然复现，单独标注故障注入的旧记录，只关闭实际已验证子范围。
6. 执行失败一次：已有成功步骤及输出保留，停止自动继续；“继续 / 重试 / 重新规划”与实际许可一致，恢复后每步均有匹配回执才完成。无回执/部分回执不能假完成。失败/cancelled Task 需要重新规划和批准，不能偷走通用续跑。
7. 保留一个失败方案，再生成不批准的新草稿；历史仍能选择原失败方案并恢复，两个记录分别保留。中断/等待任务用批准绑定入口继续原 Task；模型/推理强度不漂移。
8. 离线、过期、取消、切换项目、迟到响应分别一次；手动导入/校核/计算不依赖在线模型。恢复网络后重试只影响当前 scope；终端刷新后结果和阶段动作更新，已完成不显示旧等待理由。
