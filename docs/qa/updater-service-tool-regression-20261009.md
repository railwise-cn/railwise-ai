# 更新验收工具：真实安装包服务回归（2026-10-09）

这是更新验收工具和合成数据的本地回归记录，不是实际下载、Squirrel 安装、重启或界面验收，也不是发布批准。两个原安装包和日常用户资料未修改；没有启动界面、连接生产更新源或变更系统信任。

## 复现与原因

官方更新验收 run `37882814359` 在数据准备阶段失败，未开始原生更新。旧工具只检查 `app.asar/kun`，但当前和保留的官方 0.5.2 服务都实际位于 `app.asar.unpacked/kun`。工具因此错误地加载检出源码，工作流还没有构建该源码服务。

本地进一步以同一 0.5.3 的 Electron Node 模式运行原始工具：即使源码 JS 已构建，仍错误解析到检出目录的 SQLite 原生绑定并失败。原始代码来自 `68ab3cb39c76f44f22f0c22f3504ac82c232d023`，失败输出完整保存在下方原始报告中。

真实数据读回还发现一个工具比较问题：新读取器增加值为 `undefined` 的可选属性，而 JSON 基线不保存这些属性。修复只将读回对象归一到 JSON 持久化语义；坐标、显式 `null`、任何有值字段的变化仍失败，SQLite 历史行数量及 SHA256、原文件和工作区文件 SHA256 仍严格不变。

## 修复后的边界

目标检查及两次目标读回缺少服务、只有部分服务、依赖丢失、原生绑定加载失败或来源不匹配时，均直接失败。源码兼容服务只允许在真实 0.5.2 包缺少全部服务时用于 seed，使用隔离 staging 和该基线包的 SQLite 二进制；不声称源码服务是旧包自身的计算实现。

工作流明确构建 seed 兼容 JS 服务及依赖，以实际 Node `process.arch` 命名 artifact。运行器、远程证据验证器和发布门禁要求目标两次读回身份与验签冻结目标一致，并独立拒绝不支持的架构。

合成布局和负向测试不证明真实厂商资料、SUC 互操作、规范符合性、真实专业签认、全部插件迁移或凭据执行。本次修复合并后仍须重新冻结最终包，并重新完成真实更新往返、安装包界面检查和独立高级工程师模式 AI 验收；本记录不能替代这些门禁。
