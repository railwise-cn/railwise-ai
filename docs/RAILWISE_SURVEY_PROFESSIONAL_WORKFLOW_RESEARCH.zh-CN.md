# RailWise Survey：专业测量流程调研与 AI 产品修订方案

日期：2026-09-30。研究对象：工程测量内业人员、复核人员与成果接收方。范围：科傻 COSA、测量云的公开处理流程与成果，以及当前 WorkWise 工作区源码。

状态：研究与后续实施依据，不是新功能完成记录或发布验收。当前工作区基于 `4a52666c`，包含尚未提交的简化 UI 改动；本轮未改变计算代码、历史成果或公开版本。

## 1. 方向修正

产品应当成为**由 AI 协助完成的专业测量工作台**。用户先识别自己正在做水准复测、导线控制网还是变形监测，再由系统串联资料、检核、计算、复核与交付。

上一版把“减少界面入口”当成主要目标，后置了过多工程信息。需要修正三点：

1. **专业判断留在主流程。** 网形、已知点、坐标与高程基准、观测质量、闭合差、精度和成果表不是调试信息。它们要能直接查看，不能统统放进“高级”。
2. **成果内容先于文件格式。** 导出 DOCX/PDF/XLSX 只是载体；真正的交付是具有明确栏目、单位、检查依据、计算过程和复核记录的成果册。
3. **AI 节省整理、查找、解释和重复出报时间。** 确定性计算服务负责数值，工程师决定基准、适用规则和观测取舍。用真实任务耗时和成果正确性验收，取消“所有任务不超过 5 次主动作”的统一硬指标。

保留上一版有价值的部分：四个工作区、统一上传入口、按需打开 AI、兼容旧路由、不暴露执行协议、清晰且不透明的工作表面。需要修改的是专业内容的层级及交付结构。

## 3. 传统软件值得学习的专业结构

### 3.1 COSA：以控制网及成套计算成果为中心

由 S1–S3 可还原的工作链为：

> 原始观测整理／转换 → 控制点、先验精度及网形设置 → 概算 → 平差与精度评定 → 闭合检核与残差复查 → 成套成果。

注意：S2 示例实际先执行平差、再从工具菜单计算闭合差；其闭合差工具也可独立使用。这里归纳的是业务依赖，不声称所有版本强制采用同一点击顺序。

| 专业对象 | 资料中明确列出的产物 | 对 RailWise 的要求 |
| --- | --- | --- |
| 水准／高程网 | IN1 观测文件、OU1 平差成果、GCI 闭合线路、GCO 闭合差成果 | 原始读数、测段高差、平差高程、闭合线路分开；不能用一张“结果表”混合表达。 |
| 平面控制网 | IN2 观测文件、OU2 平差成果、CLI/CLO 闭合线路及结果、MAP 网图 | 显示方向/距离平差结果、坐标及精度、最弱点、边长方位角及相对精度、最弱边、单位权中误差与加权残差平方和。 |
| 水准沉降分析 | Word 平差报告、Excel 沉降报告与曲线，见 S1 | 平差成果与多期变形分析应有关联，但不能把坐标改正数当成变形量。 |
| 高级方法 | 不同版本声明自由网、拟稳、方差分量估计、CPIII、贯通影响等 | 按明确适用范围逐项验证，不因具备一个试算核就宣称全面对等。 |

主要启发：专业性来自“每个数是什么、如何得到、能否复核”，而不是菜单多少。文本文件规则、手动搬运和重复配置才是适合优化的操作成本。

### 3.2 测量云：把外业、测期和成果生产串起来

S4 明确的导线流程为：下载项目 → 下载外业数据 → 设置处理参数 → 平面已知点 → 必要时高程已知点 → 单期/多期平差 → 成果坐标变化分析。电子手簿、质量检查、查看原始数据与格式转换仍可访问。

S5–S8 还给出三个重要细节：

- **水准处理先有测段。** 转点识别、测段合并、点号对应不是普通 CSV 清洗；同一个点在不同时期的对应关系会影响后续结果。
- **复测需要专门比较表。** 本期测段高差与原测高差的差值，应形成可筛查、可导出的表，不能只画两条趋势线。
- **监测有时间语义。** 后加入的测点、测点重设初始值及累计变化接续，需要显式期次记录。不能将全项目第一条记录一律当成所有测点的永久初值。

已查看的 S8 日报样例包含：点号、初始值（m）、上次累计变化（mm）、本次变化（mm）、本次累计变化（mm）、变化速率（mm/d）、控制值、预警状态、备注；并具有工程信息、观测/计算/校核信息、工况、说明和页码。其数值、限值、符号约定属于样例，不作为 RailWise 默认值。

S6 网图中可直接看到控制点与普通点符号、测段箭头、高差和距离。图是检查工具，也是成果的一部分。

## 5. 修订后的产品流程

### 5.1 入口与信息层级

新任务采用明确的作业类型：**水准网与复测、导线与平面控制网、变形监测**。GNSS/CPIII 等在能力范围得到对应验收后进入相应任务模板，现有功能保持可访问。

每种任务都沿用“概览 / 处理 / 结果 / 交付”，但页面内容按任务变化：

| 页面 | 默认可见 | 按需展开 |
| --- | --- | --- |
| 概览 | 作业类型、测期、资料完整性、当前问题、下一步 | 项目行政信息、历史版本 |
| 处理 | 资料清单、网形/测段、已知点与基准摘要、观测检核、计算准备；当前需要处理的问题 | 完整观测表、规则明细、仪器与改化参数。关键设置仍有常规入口，不藏入技术高级区。 |
| 结果 | 任务专用成果表、闭合检核、精度摘要、异常观测；表格/网图/原始记录联动 | 完整协方差、统计试算、算法与来源版本 |
| 交付 | 专业成果册目录、各表页预览、缺项及复核状态、导出 | 哈希、内部清单、运行参数和不可变修订链 |

AI 以“整理资料”“解释这条超限”“比较两期”“生成成果说明”等具体动作出现，也可自然语言提出目标。允许工程师直接操作表格完成同一流程。AI 打开时不应遮住当前待解释的观测行或成果表。

### 5.2 水准网／复测

1. 导入原始仪器文件、已知高程与必要的原测成果；保留原件。
2. 形成测站/测段，建议识别转点和往返关系，展示点号对应；无法确定的关系显式待确认。
3. 按实际可用字段进行观测检核；视距、前后视距差、读数与测段往返差等检查必须有相应原始量，缺量不可假装已检查。
4. 确认高程基准、已知点、定权方式及适用等级/限差来源，展示闭合线路和超限项。
5. 计算并显示高程、改正数、精度及最弱项；异常可回到具体观测。
6. 有原测数据时生成高差之差或复测比较；有多期数据时进入变形分析。两种比较不能混成同一个指标。
7. 生成水准成果册及配套表格。

### 5.3 导线／平面控制网

1. 导入测站、方向、距离及已知点，检查同名点、轴序、角度编码和单位。
2. 检查测回/归零等原始观测质量；已仅包含归算值的 IN2 不应声称拥有外业全量检核。
3. 确认坐标系、中央子午线、投影面及适用改化参数，列出已应用、未应用和不适用的改化，避免重复改化。
4. 形成网形与独立闭合/附合线路，显示真实角度、坐标、全长和相对闭合检查。
5. 平差后检查方向/距离改正数、坐标及精度、误差椭圆、最弱点与最弱边。
6. 与历史成果比较并生成专业成果册。

这是目标业务合同；并不表示当前代码已完成每一种改化、检核和最弱边计算。

### 5.4 变形监测

支持两条明确路径：仪器观测 → 平差 → 各期成果；或外部已平差成果 → 字段/单位/来源确认 → 多期分析。后者注明外部结果来源及本产品未重做的检查。

按测点维护初始期、上期、本期、符号约定、控制值及变更记录；点位重设时新增可追溯事件并预览累计接续影响。输出本次/累计变化、速率、控制值、预警、曲线、工况说明及异常处置。数据不足或日期间隔不明时不生成伪精确速率。

| 水准网平差／复测成果册 | 项目与基准说明、控制点、原始记录索引、测段及往返比较、闭合线路/限差、平差高程及精度、观测改正数、网图、原测高差比较、异常处置 | DOCX/PDF 用可打印专业表格；XLSX 使用中文表名、明确数值类型/单位、冻结表头及打印区域。缺项列明原因。 |
| 导线／平面网成果册 | 已知点、仪器和定权、改化参数/前后值、概算与网图、观测检核、闭合检核、方向距离平差表、坐标精度表、最弱点/边、椭圆、复测比较 | 坐标 m，改正数与中误差按列显示 mm/角秒等；存储精度与显示舍入分开。DXF/其他交换格式须独立验收后提供。 |
| 沉降／位移日报与阶段报告 | 点号、初始值、上次/本次/累计变化、速率、控制值与预警、曲线、工况、异常说明、计算和校核信息 | 按测点/监测项/测期一致分组；不从一般趋势自动推断施工因果。模板版本与数据版本固定。 |
| 复算与审查附件 | 原始资料目录、使用/排除的观测、参数依据、各次修正、计算版本、审查意见与修订链 | 保留机器可读证据；工程师可从成果行一键定位原记录，不要求先理解哈希。 |

共同要求：封面与目录、工程信息、成果日期/版本、编制/复核/批准状态、页码、跨页表头、单位、舍入规则、图例和缺失值说明。签名栏空白就是未签，不由 AI 填写身份或批准结果。

报告模型应先形成统一的“成果数据、检查结论、图表与证据引用”，再渲染 DOCX/PDF/XLSX。AI 只能根据这份冻结模型编写说明，不能另算或改写表中的数。

## 7. AI 怎样产生可衡量的价值

下表为产品提案，不是已交付能力或已测效率收益。

| 工作 | AI 与自动化的具体配合 | 工程师控制点 | 验收方式 |
| --- | --- | --- | --- |
| 资料整理 | 解析器提取文件事实；模型关联任务、测期、点号别名和缺件，给出带原文件位置的整理建议 | 确认歧义点号、单位、来源和基准；未知格式不猜测放行 | 与人工整理的文件/点号/测期映射对照；记录误合并、漏项与人工分钟数。 |
| 问题定位 | 计算服务生成超限或不可检验项；AI 解释含义并关联测站、测回、测段和可能原因 | 决定保留、重测、修正或排除；原因只是待核实假设 | 已知注入问题能否定位原始观测；不能把异常候选说成已证实粗差。 |
| 参数准备 | 从已批准项目模板和可信元数据预填规则/仪器参数，逐项说明来源；只有缺项或变化时要求确认 | 基准、改化、定权、等级和规范适用性 | 同项目续期减少重复输入；参数变化必须提示，缺来源不能自动批准。 |
| 方案比较 | 在隔离试算中比较两个明确模型/取舍方案，列出坐标、残差和精度差异 | 选择方案及说明理由 | 原始数据不变；两方案可独立复算；不能以“更接近合格”作为自动选优目标。 |
| 多期分析 | 自动对齐测点和测期，识别缺测/新点/初值变化，再结合现场记录起草变化说明 | 初值接续、监测阈值及工程原因确认 | 正确处理新点、断测、乱序、单位和符号；不编造工况因果。 |
| 成果生产 | 自动组装专业表格与图，模型生成受证据约束的文字；数据变更后标出受影响页 | 专业复核与签认 | 三格式数值一致、引用准确、缺项可见；错误/旧数据不能带入当前结论。 |
| 结果问答 | 回答“该点为何较弱、这条线路为何超限、与上期差在哪”，每个数值连接对应结果行 | 工程师复查并采取动作 | 提供数值、单位、来源和适用边界；证据不足时明确不能判断。 |

这些能力继续扩展现有 `kun` 工具与任务合同，不新增第二套智能体运行时。建议将 AI 执行范围分成：只读解释可直接执行；批准范围内的确定性整理/计算可自动串联；改基准、改权、排除观测、重设初值和签认分别保留明确授权。

不能由模型直接决定或生成：缺失的真实观测、未知坐标基准、未核实的规范限差、自动删点、受检成果合格结论、真实签字、把统计显著等同结构安全。专业规则必须来自受控规则与明确的项目适用性。

## 8. 新优先级与实施依赖

整体顺序：**成果合同与数值语义 → 水准完整闭环 → 平面控制完整闭环 → AI 批处理与证据解释 → 长尾专业扩展**。UI 和报告必须随对应任务一起完成，避免只做页面入口。

| 优先级 | 工作包 | 完成条件与代码落点 |
| --- | --- | --- |
| P0-1 | 专业结果与成果合同 | 固定三类成果的栏目/单位/依据/缺项规则；区分闭合差、残差范数、坐标改正与位移、先验/后验精度、检查与签认。扩展 `kun/src/contracts/` 与现有 Survey 服务；保留旧字段读取及历史语义。 |
| P0-2 | 第一条旗舰链：GSI／明确映射的 IN1 水准网与复测 | 从原始记录、测段和基准到闭合、平差、专业成果册全程可复核；已知/异常/缺件案例独立对照；标准和限差未定时状态明确。复用现有水准核及来源账本。 |
| P0-3 | 专业成果模型、表格模板和打印验收 | 替换单纯逐行段落式成果呈现；水准成果表、闭合表、精度/改正数表、网图及索引首批落地。保留现有证据 XLSX/清单兼容。检查 Word/PDF/Excel 实际阅读和打印效果。 |
| P0-4 | 页面恢复专业主线 | 在四工作区内恢复网形/已知点/检核与专用成果表；修订 `SurveyAdjustmentPanel` 和 `EngineeringWorkspaceView`。关键确认可见，技术协议后置；窄窗口不靠缩小表格字体。 |
| P0-5 | 第二条旗舰链：COSA IN2 平面控制网 | 使用受控的相同原件和参数对照 COSA 输出，逐项比较坐标、改正数、精度和适用闭合；验证该版本报告。不得仅凭历史 33 点坐标接近关闭全项。 |
| P1-1 | 测量表格映射与批量资料整理 | CSV/XLSX 测量点/观测映射、线性单位、角度编码和基准保存后可复用。AI 生成建议，确定性校验准入；不把监测表支持当作测量表支持。 |
| P1-2 | AI 问题定位、精确解释和有界编排 | 把上述数值合同接入既有只读问答和任务执行；增加多文件整理及安全连续计算；明确失败恢复点、过期结果和歧义确认。 |
| P1-3 | 多期复测与监测生产 | 点号对照、测段高差比较、初值/重设事件、累计接续、日报/阶段模板；完整异常场景及历史保全测试。 |
| P1-4 | 规则适用与复核闭环 | 项目规则版本、限差来源、问题处置、复核记录和真实角色签认；计算完成不能直接等于可正式交付。 |
| P2 | 更广格式、GNSS/CPIII 专项、高级方法及外业联动 | SUC 语义/单位/协议与样本先取证；再做支持合同和互操作。一般自由/拟稳、VCE/抗差生产接线、大规模、DXF、仪器实时连接按实际需求分别验证。 |

P0-1 是其他工作包的前置依赖；P0-2 与 P0-3 共同验收第一条闭环，P0-4 服务该闭环，随后完成 P0-5。AI 精确解释已有基础可随 P0 使用；P1 指增量完善，不是暂停所有已有 AI 功能。

优先水准的原因：已有 GSI/水准内核和历史验证基础，能同时覆盖控制测量、复测和沉降成果；平面控制链紧随其后，并以已有 IN2/OU2 对照为起点。顺序是基于当前资产与工程流程的产品判断，尚无用户样本证明其商业收益排序。

## 9. 验收从“少点几次”改为“更快交出正确成果”

### 专业正确性

- 每条旗舰链有受控原件、已知点、坐标/高程基准、单位、仪器精度与定权、改化清单、规则版本、参考成果和容差说明。
- 同一资料在合法可用的参考软件或独立实现中复算。比较的不只是坐标，还包括观测改正数、闭合线路、自由度、方差尺度、精度、最弱项与图表栏目；参考软件也不是绝对真值。
- 事先确定比较容差及其来源；区分打印舍入、数值误差和工程限差，不能事后放宽容差以追求通过。
- 异常样例至少包含单位/角度编码错误、同名点冲突、基准不明、断网、冗余不足、已知粗差注入、已改化数据重复改化、过期输入和损坏原件。
- 缺原始测回或站内读数时，相关检查状态必须为未评估；“成功解析”“可求解”“限差合格”“已复核”分别表达。

### 成果质量

- DOCX/PDF/XLSX 与界面使用同一冻结结果；行数、单位、舍入、空值与数值逐项一致。
- 长表换页、重复表头、中文字体、图例、签认栏、页码与打印区域在真实阅读器检查；查看文件存在或哈希一致不足以完成排版验收。
- 任一成果点或异常能定位到测段/观测及原文件；更改已知点或参数会使依赖成果失效并生成新版本，不覆盖旧成果。

### AI 效率与可靠性

- 用同一批正常和异常任务，记录传统流程/现有版本/新流程的人工分钟数、返工次数、字段修正次数、成果差错、AI 建议采纳与纠正数量。
- 分别测量资料整理、问题定位、首次有效结果、成果编制的耗时；每组标明样本量及任务复杂度，不用一次合成 CSV 的四次点击代表生产效率。
- 单独统计 AI 数值/单位/引用错误、错误合格判断、无依据修改及恢复成功率；没有实际测量前不承诺“提高 80%”。
- 最终打包应用由 computer-use 检查主题、语言、窗口、键盘和专业表格，并由独立的高级工程师模式 AI 审查软件与产品行为。此模拟审查不替代授权厂商/SUC 对算、真实专业签认或法定授权；公开发布仍由用户明确批准精确版本和操作。

## 10. 仍需取得的证据

- COSA 和测量云具体可使用版本、合法使用环境及同一任务的真实原始文件、设置和完整成果。既有历史参考可复用，但不能代替当前版本复验。
- 适用项目的成果格式、技术设计书/约定及限差依据；公开竞品截图只能启发结构，不能作为所有工程的统一规范。
- SUC 的可验证语义和兼容权限；教程说明可以导出 SUC，不等于公开了足够实现可靠解析的格式规范。
- 少量有代表性的工程师任务观察，用于量化重复劳动和比较新流程。现有公开资料可以支持上述设计修订，不能证明痛点频次和收益百分比。
