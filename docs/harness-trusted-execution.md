# Harness：可信执行与连接器闭环

本次变更沿用本机 KUN Runtime。钉钉和飞书是独立 Provider；模型看见的工具来自当前真实目录，不能用 Shell、说明文字或生成的命令替代平台执行。

## 生产路径

聊天、写作、已有任务补充、IM 和 Schedule 经过 TaskCoordinator。状态查询只返回本地快照，不创建 Turn、模型请求、操作回执或历史文件写入。新外部请求在分配 Turn 前检查连接器、身份、实际 scope 和执行权限。阻断请求保留为 waiting_user，并显示连接、安装、登录或设置入口。授权更新后重新预检并继续原任务，不把新 Provider 的权限悄悄加到旧 Worker。

Turn 保存服务端确定的 Provider 身份及不可变 ExecutionGrant。实际派发再次检查工作区信任、Agent 范围、沙箱、路径、网络、连接器 scopes 和当前租约。workspace-write/read-only 的普通目录不包含主机 Bash，旧工具解析入口也不能绕过限制。子任务只处理允许的资料与候选文件，不获得外部写操作或自行提权工具。

飞书/Lark CLI 与钉钉官方 DWS 的安装、设备登录和诊断由主进程管理；Runtime 读取可信本机诊断配置并热刷新。连接器和技能集中在同一入口的独立页签，点击连接后进入官方配置或扫码，不提前索要账号。钉钉原 OAuth/OpenAPI 企业应用配置保留为高级兼容入口，个人用户令牌与企业内部应用 Workflow 权限继续区分。两个平台均不接受模型提供的 CLI 路径、Shell、API host 或操作者身份；受管理 CLI 使用隔离凭据目录，原配置及凭据引用继续保留。

## 验收范围与回执

“处理待办”没有有限完成边界。模型先通过真实读取工具取得待办，再提出最多八个精确 Provider／动作／目标的完整集合，由用户确认后持久保存。确认集合不可缩减、替换或扩张；每个目标的写入仍需明确确认。详情任务可确认精确读取目标，列表任务固定绑定当前授权账户。

输入入队、集合确认与实际完成是不同状态。完成要求集合中每一项都有可信工具回执和目标状态验证；单条说明、一项成功或一份方案不能代替全部成果。任务详情展示平台、目标、验证证据和操作状态，不展示内部 Session、Worker、Thread 或 Turn ID。

回执保存请求指纹、Grant、确认集合引用和安全的核验定位字段；不保存评论正文、令牌或任意请求内容。真实审批允许后、派发前持久保存批准证明。审批等待期间 TaskRun revision 的变化不会让未改变的范围误判失效；独立的 scope revision 防止用旧确认替换新范围。

同一任务恢复后，已成功目标复用原回执，新的模型 call ID 不会重发。接受历史回执时核对同一任务持久 execution attempt，不能借用其他任务或未知 Turn。相同目标改用不同参数产生冲突。结果未知时保留原回执，先通过只读核验取得独立证明，禁止自动重放写操作。未能核验的记录继续显示待核实。

整任务重试会检查原任务及其全部重试祖先的操作账本。尚未核实的工具或进程阻止创建新执行；已派发的外部写操作不能通过新任务账本再次执行。读取成功和明确未派发的失败可重试。核验成功仅说明原动作结果，不能作为重放写操作的授权。

## 一次主机命令授权

普通只读和工作区写入目录继续隐藏 Bash。需要主机命令的非连接器任务可以提出 `request_host_shell`，用户审阅完整命令、工作区、哈希和有效期后，才通过已有 Shell Adapter 派发一次。批准绑定当前任务、Turn、不可变执行租约和权限版本；不修改工作区信任，也不把主机 Shell 变为常规工具。子 Agent 和外部平台 effect 任务没有此入口。

会话仅允许轮询或停止原命令，不允许发送 stdin 或借旧授权执行新命令。同一任务在新 attempt 可只读查看原命令；发送停止信号仍要求原授权和原租约。进程身份不明、命令结果未知时不得自动重启或宣称完成。钉钉、飞书等常规操作继续经过类型化 Provider。

## Flow HTTP 节点兼容迁移

旧 HTTP 节点及其配置、发布版本、运行历史和定时任务全部保留，不删除、不归档整个 Flow。通用 HTTP 节点现在只发送 GET/HEAD 读取；原 POST、PUT、PATCH、DELETE 等写节点，以及访问钉钉、飞书/Lark 官方域名的节点（包括读取）会在发出请求前失败，错误码为 `external_effect_requires_typed_provider`。原因是这些旧节点没有任务授权、目标确认和操作回执，不能承担外部平台执行。此类阻断不自动重试，也不接受旧“忽略错误继续”策略转换成成功；其他节点和已保存成果不被删除。

用户应保留原节点用于核对参数，在任务工作台连接相应平台，将业务目标改为该平台的类型化任务，由真实读取工具选定目标并通过授权卡片确认写入。现有 Flow 通用 Agent/HTTP 节点没有可替代授权账本的连接器写入入口；在具备该入口前，外部操作保持阻断，不用 Shell、HTTP 代理或切换平台绕过。公开 HTTPS 读取可继续使用 GET/HEAD；重定向和 method-override 请求头不会绕过本限制。修改后的 Flow 需重新发布，历史版本仍可查看。

## 工作区与兼容

Flow 的通用 `publish`、`archive` 和 `subagent` 节点保留为不可执行的历史节点。原发布节点没有目标授权和回执，原归档节点只是透传，Flow 子 Agent 缺少可继承的真实父任务执行身份；因此目录明确显示不可用原因和替代入口，旧已发布 Flow 或节点测试也会在派发前返回 `flow_node_unavailable`，不能以重试、忽略错误或注入适配器变成成功。原节点、配置、版本、调度和运行历史均保留。用户应保留原参数，改用任务工作台的类型化平台任务或持续文档交付，并重新发布修改后的 Flow。普通 Task 子 Agent、持续文档交付以及写作保存与导出保持可用。

保留 `.workwise`、旧 IPC/config、凭据引用及用户文档。迁移服务盘点 `.workgpt`、`.workwise`、`.kun`、`.deepseekgui`，按指纹报告重复和冲突；用户确认后创建独占、可校验快照，原件不移动、不覆盖。活跃 SQLite 必须走一致性备份，不能声称普通文件复制是数据库备份。

侧栏只合并实时 realpath 已核实的别名；同名或内容相同的独立目录不隐藏。工作区显示名称可编辑，目录和历史身份保持原值。显式清空工作区时退出该聊天的可见选择，后续新建不能暗中复用旧默认路径；运行中的任务保留。没有删除或替换插件、MCP、Skill、凭据引用或用户文件。

## 验证与发行边界

### 任务范围与实际执行权限

任务详情与能力阻断卡接入同一个权限面板。用户可确认当前任务最长 15 分钟的范围，或选择下一次真实工具操作。读取调用也计入一次操作。服务端在审批通过、执行租约核验后原子登记消费，拒绝审批保留待用授权，操作结果未知时保留消费记录。授权确认后由用户继续原任务。

任务范围分别记录可读路径、可写路径、网络来源、Provider 与已确认外部目标。工作区和 Agent 的只读边界持续有效。类型化文件工具对授权路径进行真实路径核验，网络读取逐次检查重定向来源。每次 Turn 保存实际工具目录和权限，任务详情直接展示该持久记录。子任务继承并收紧父权限，派发时重新检查父任务授权、工作区和 Agent 版本。

### MCP 配置热应用与历史连接器

主进程从已保存的配置和本机凭据存储生成 MCP 快照，通过专用 Runtime 接口应用。通用 renderer 请求桥拒绝直接提交此配置。Runtime 串行核对版本和请求摘要，将同一连接器目录应用到主任务与子任务，并更新能力清单。凭据仅保留在该连接器版本的内存中。新配置撤销后续派发，已接受的调用继续等待结果，旧客户端在在途调用结束后关闭。

实际 MCP 配置、账号凭据和工具 schema 的摘要进入执行授权。配置或账号变化后，原 Turn 需要新的执行授权才能调用变更后的连接器。搜索模式同样核对目标服务的摘要。原插件、MCP 配置、Skill、凭据引用及历史回执保留。

历史 MCP 的显式环境变量引用继续读取。V2 凭据删除会撤销对应旧注入值。连接中断后，自动重试只适用于应用已确认的只读工具。其他已派发调用保留结果待核实状态。用户可以保留原连接器配置，重新检查连接与权限后继续任务。预置只读连接器的工具清单没有匹配项时，界面显示当前不可用。

### 数据迁移与文档格式

四个历史命名空间的工作区快照使用 SQLite backup 取得包含已提交 WAL 内容的一致性数据库。启动时的旧资料导入使用 SQLite 读事务固定图像，校验内容后再提交目录。WAL 和 SHM 留在源目录，由数据库图像承载已提交内容。插件配置、MCP 配置、Skill 正文和凭据引用按内容核验并保留。多个历史来源有不同内容时保留双方并等待选择，有内容的来源优先于空目录。旧迁移记录继续使用原校验方式读取。

研究报告等现有交付模板提供实际文档服务状态、当前模型和配置入口。用户可以明确选择 Markdown 草稿，或增加 DOCX、PDF。新任务按所选格式逐项验收，历史任务沿用原格式要求。模型连接和每种文档导出结果在执行时核验。

自动化回归使用合成账户、固定 HTTP/CLI 回包、真实 SQLite、真实 Runtime 装配和本机子进程，覆盖预检、拒绝、授权、scope 收紧、输入隔离、有限目标集合、历史回执、未知结果、任务界面及兼容读取。模拟 Provider 和模型结果不代表真实平台验收。

用户在官方页面完成扫码、账号选择与权限授权，无需提前在聊天中提供账号、密钥或测试 ID。飞书首次应用配置与账号授权为不同步骤；钉钉组织可能需管理员开启 CLI 访问。实际写操作验收到执行阶段再选择明确的合成待办或测试审批目标。实现期间不自动操作真实业务审批。精确依赖构建、安装包身份/签名/适用公证以及中文平台界面验收分别记录，缺少证据时不称发布就绪。本次不修改公开版本号、渠道或已发布资产。

实现来源：`kun/src/services/task-coordinator.ts`、`task-controller.ts`、`external-effect-evidence.ts`，`kun/src/adapters/tool/*-tool-provider.ts`、`sandbox-policy.ts`，`src/main/services/workspace-migration-service.ts`，任务与连接器设置界面。Provider 协议说明见 [Lark](qa/harness-lark-provider.md) 和 [钉钉](dingtalk-provider.md)。

连接器工作台的入口、状态和迁移说明见 [技能与连接器工作台](connector-workspace.md)。DWS 官方工具已核实存在，此前“dws 不存在”的判断不再作为产品约束；禁止的是未经核实的命令和通过 Shell 绕过类型化权限。

## 通用技能和网页成果

市场安装状态分别记录技能资料、Runtime 加载版本、运行依赖、连接及执行权限。安装和更新通过版本化根目录清单同步到 Runtime，当前执行保留自己的技能版本。BrowserSkill 使用校验过的固定 CLI 和官方浏览器扩展，类型化 Provider 管理任务浏览器会话及站点范围。扩展断开、协议不兼容和实例变化会产生具体能力阻断。

普通聊天中的文件交付、网页采集和周期要求进入统一任务。HTML 成果使用 `publish_artifact` 保存到 Runtime 分配的任务目录，并登记回执、大小及 SHA-256。这个目录属于独立成果能力，普通文件工具仍按自己的路径范围执行。用户指定工作区保存位置时，权限卡负责确认实际路径。

有效 HTML 通过 `taskId`、`artifactId` 和摘要取得受限预览地址，在当前任务右栏自动打开。服务逐文件复核成果清单和内容，页面在隔离上下文中运行。源码、完整命令及内部操作字段通过主动展开的详情查看。默认报告样式随文件提供，可离线阅读和打印。

## 临时范围授权与控制事件

当前任务的临时权限默认最长十五分钟，支持下一次操作和限定任务期限。确认的内置文件读写范围在派发时复用，每次仍复核真实路径、Grant 版本及有效期。工作区默认只读可通过明确的任务级目录例外授权，Agent 和显式沙箱的硬限制继续参与计算。空闲任务可重新确认范围，新的权限 ID 使旧执行凭证失效。

`DELETE /v1/tasks/:id/permissions` 使用原权限 ID、任务 revision 和幂等键撤销临时范围，并暂停原任务。原授权及已经派发的操作留在账本，未知结果继续核验。权限面板提供该动作，恢复原任务需要有效的新授权。

审批决定保留独立来源，经过 outbox 和检查点确认后消费。在线决定解除原审批等待，恢复时依据持久位点处理。聊天中的审批状态来自原审批记录，内部回执无需作为普通用户输入。历史记录只有在任务数据库关联能够核对时才调整显示，原会话文件仍保留。

## 每日计划和来源证据

每日计划采用目标时刻、提前量及 IANA 时区的统一合同。创建计划和读回计划都有实际持久记录，修改时间后重新计算下次执行。调度 outbox 经 TaskCoordinator 派发普通任务，每轮使用原计划授权范围及新的执行凭证，保存本次成果。应用退出或休眠期间的恢复使用已有有界规则。

采集任务的完成验收检查真实工具读取及来源元数据，显式指定的来源逐项核对。HTML 文件与每日计划分别满足文件和计划验收要求。网络错误的有界重试按来源和工具记录，其他可用来源与浏览器能力继续保留。缺失的搜索 Provider 不进入可执行工具目录。
