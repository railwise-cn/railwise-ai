# 桌面界面与自适应布局

本轮统一导航、工作面和成果面板的布局，重点修复智能体选择器、应用界面缩放和窗口尺寸变化造成的错位。官网不在修改范围。

## 布局约定

以工作台容器实际可用的 CSS 宽度计算，不根据显示器分辨率猜测，不把小窗口按一个更大的窗口强行分栏。应用自身的界面缩放也会改变可用空间。

| 可用宽度 | 导航 | 成果与工具 |
| --- | --- | --- |
| 小于 1024 | 按需打开抽屉 | 按需打开抽屉 |
| 1024 至 1279 | 左侧停靠 | 按需打开抽屉 |
| 1280 及以上 | 左侧停靠 | 右侧停靠，保留至少 480 宽的主要内容 |

同一时刻只显示一个活动抽屉。背景不接收点击和键盘输入；按 Escape、关闭按钮或点击遮罩可返回原工作面，焦点回到触发控件。普通窗口和宽屏中的面板分隔线支持鼠标和方向键调整。

导航、聊天、任务和成果使用一致的文字、边界和间距。导航内容和工作面保持不透明，装饰性渐变不承担内容层级。短窗口允许导航内容滚动，底部更新和设置入口有独立空间。

成果面板只挂载一次；从停靠变为抽屉使用同一页面实例。选择当前任务后，窄窗中的导航自动收起，不另开第二列任务列表。

## 选择菜单

智能体和模型菜单使用统一锚定逻辑。菜单跟随实际触发按钮，在滚动、窗口尺寸、容器尺寸及界面缩放变化后重新计算位置；宽高不超过当前可用视口。长列表在菜单内滚动，供应商与模型在同一面板选择，避免多级侧弹重叠。键盘选择、Escape、外部点击和焦点恢复使用相同规则。技能、文件和命令联想保留输入框焦点，扣除同一工作面顶部栏后按输入框上方实际空间限制高度；标题保持可见，方向键选择只滚动内部列表，菜单背景不透出正文。

## 偏好与资料兼容

保留旧侧栏宽度、收起状态和成果面板模式的配置键。自动适配后的临时宽度不覆盖用户保存的宽度；重新拉宽窗口后恢复偏好。紧凑窗口中打开或关闭导航不改变宽窗口中的收起偏好。首次启动的新默认导航宽度为 264；既有偏好在新的可读范围内使用，用户可重新调整。插件、Skill、MCP、凭据、工作区及任务历史均不迁移或删除。

## 依据与验收

采用 [Google 的可用窗口尺寸分级原则](https://developer.android.com/develop/ui/compose/layouts/adaptive/use-window-size-classes)，并参考 Apple 对[侧栏自动适配](https://developer.apple.com/design/human-interface-guidelines/sidebars)及[单一锚定弹出菜单](https://developer.apple.com/design/human-interface-guidelines/popovers)的建议。这是 RailWise 的桌面实现，不声明取得这些厂商的设计认证。

自动检查覆盖真实容器尺寸变化、窄窗抽屉、偏好恢复、最小内容宽度和键盘焦点。最终验收仍须在最终精确安装包中检查中文界面的窄窗、常规窗口、宽屏、短窗与界面缩放；开发服务或 DOM 测试不能代替精确包实测。既有 84ae 截图保留其原源码标记，不作为本轮新界面的截图。


## 实施与验证记录

工作台布局、选择菜单、设置及帮助适配已合入同一分支。桌面全量回归在固定 Node 22 下通过 4,725 项、跳过 10 项；旧成果预览测试已随单一根级面板结构更新并通过，未把面板移回多处挂载。恢复入口合并后，新增卡片、任务页、preload 与 IPC 聚焦 120 项通过，桌面及 Runtime 类型检查、相关 59 文件 lint 和生产构建通过。完整 Runtime 与最终源码 CI 另外记录其结果。

已实际安装并打开签名、公证通过的 `ea91280a` macOS 0.5.7 包，在中文界面检查以下组合：960×640 与大字号、1336×731 与中字号、1600×900 与小字号。实际检查了 General 与模型的定位、滚动、End/Escape 和焦点返回，侧栏底部入口、单一左侧任务列表，以及设置和帮助目录、搜索。窗口从宽屏缩到窄窗时，成果面板变为抽屉，同一预览页面的实例、地址及加载时间保持不变，没有重新加载。检查后通过实际设置恢复原字号和窗口尺寸；任务、回执、未知结果记录、会话及凭据配置保持不变。

该包尚不包含最后的长输入联想菜单修复。后续 `10898d7f` 精确包已安装、验签并实际打开。追加实测发现：18 行长输入时，技能菜单标题仍可能被工作面顶部标题栏遮挡；文件菜单按方向键移到末项时，列表没有随高亮行滚动。只有视口矩形为正不能记作视觉通过。这两项按同一工作面的实际可用区域及内部列表滚动修正，最终精确包需复查。实测还发现任务交付说明直接显示 Markdown 标记，已经改为安全的静态 Markdown，文件引用归属相应任务工作区；这项后加改动也须进入下一精确包检查。它不执行 HTML 代码块或远程图片。

上述界面证据不替代浏览器业务、Windows 或下一精确包验收。`10898d7f` 的一个完整 CI 在恢复证明阶段超时；保留原失败，并优化重复读取历史回执的查询，不放宽原浏览器恢复测试的 30 秒断言。只有最终源码与实际安装字节对应的通过项才能记为最终验收。

实际精确包中已确认的输入框入口是智能体和模型。当前任务权限从任务详情面板查看与处理；未挂载的执行设置组件不计为生产入口或实际菜单验收。
