# BrowserSkill 浏览器连接与技能更新

## 连接流程

在「技能与连接器 → 连接器 → BrowserSkill 浏览器」安装 CLI 与配套技能，在 Chrome 或 Edge 安装官方扩展，然后点击「连接浏览器服务」。连接检查列出真实浏览器实例后，选择实例、允许访问的 HTTP(S) 站点和交互范围，再保存配置。任务中的缺失能力卡片可直接打开此设置。授权和继续任务分别操作。

受管理的 CLI 固定为 0.4.0，支持 Windows x64、macOS Apple Silicon 和 Intel。归档、许可证和可执行文件分别保存摘要。扩展使用官方商店入口，运行时核对实际协议版本和所选实例。Windows arm64 返回明确的版本不支持状态。

当前任务保存浏览器实例、配置版本和站点范围。更换浏览器或修改配置后，原任务显示范围确认卡片，展示当前实例及保留的原站点范围。确认采用任务版本和浏览器版本检查，确认完成后仍由用户继续原任务。后台恢复和计划任务保持原绑定。

## 执行边界

模型获得结构化浏览器工具。读取页面、HTML、截图和访问授权站点使用当前任务授权。HTML 保留链接与截断信息，可从已观察链接获取下一页地址。后续导航使用新鲜页面 context。

点击、填写和按键可能改变网站数据。单次交互显示操作确认。重复点击或填写可通过 `browser_authorize_action` 申请 15 分钟的具体操作授权。服务端读取真实元素 HTML，绑定任务目标摘要、浏览器实例、站点、元素摘要、完整输入值摘要及权限版本。目标、输入、配置或任务发生变化后需要重新审阅。按键操作保留逐项确认。页面按钮名称只作为页面资料。

每个任务拥有独立 Agent Window。会话创建先记录可恢复请求，再创建及确认会话归属。页面读取在前后核验页签和最终 URL，越出范围时阻断正文返回。浏览器动作响应表示动作已执行，业务成功仍需观察页面或核验平台结果。

取消或退出会停止应用管理的任务会话。应用仅停止自己启动的 foreground daemon。已存在的共享 daemon 保持外部归属。

## 旧技能与配置迁移

0.5.6 中安装的 `browser-skill` 技能资料继续保留。新版本新增受管理 CLI 和连接器设置，既有技能安装无需重复替换。技能资料安装后显示浏览器连接设置入口，连接检查通过后再执行任务。

技能安装、更新、停用和回滚会保存实际根目录清单及递增版本，并向已运行的 KUN 发送刷新请求。Runtime 确认新目录加载后，后续 Turn 使用新清单。旧版本文件保留在安装历史，过期的受管理目录退出当前发现清单。用户自定义目录与旧配置读取路径继续保留。

BrowserSkill 中文匹配词和主机适配说明引导模型使用真实结构化工具。官方技能资料中的 CLI 示例保留原文，RailWise 的主机说明明确对应的受管理执行入口。

## 本轮验证边界

已通过生产 ManagedBrowserSkillService 的真实 macOS arm64 CLI 安装、版本检查、独立 foreground daemon 启停和协议 1.7 检查。首次 Node 网络下载失败后，使用官方来源正常 TLS 下载同一固定归档，再经过生产下载器的大小和摘要验证。此记录验证安装与执行依赖，国内镜像的首次下载单独验收。

自动回归覆盖缺失连接器时零 Turn、任务原始请求持久化、同一 Runtime 技能热更新、中文激活、旧版本目录退出、站点范围、实例变化、有限交互授权、过期和暂停、未知会话创建恢复及单任务会话归属。

真实扩展连接和安装包内端到端采集结果由本轮候选包验收记录补充。仅 CLI 和 daemon 检查通过时，界面继续显示等待扩展连接。
