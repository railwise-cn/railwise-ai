# BrowserSkill 浏览器连接与技能更新

## 连接流程

在「技能与连接器 → 连接器 → BrowserSkill 浏览器」安装 CLI 与配套技能，在 Chrome 或 Edge 安装官方扩展，然后点击「连接浏览器服务」。连接检查列出真实浏览器实例后，选择实例、允许访问的 HTTP(S) 站点和交互范围，再保存配置。任务中的缺失能力卡片可直接打开此设置。授权和继续任务分别操作。

受管理的 CLI 固定为 0.4.0，支持 Windows x64、macOS Apple Silicon 和 Intel。归档、许可证和可执行文件分别保存摘要。扩展使用官方商店入口，运行时核对实际协议版本和所选实例。Windows arm64 返回明确的版本不支持状态。

当前任务保存浏览器实例、配置版本、站点及交互范围。更换浏览器或修改配置后，原任务显示范围确认卡片，展示当前实例及保留的原站点范围。仅阅读任务需要搜索框填写等交互时，先申请本任务的交互范围；没有该范围时不广告或派发交互工具，也不先弹出无效操作审批。确认采用任务版本和浏览器版本检查，确认完成后仍由用户继续原任务。暂停任务保持暂停，子任务不能超过父任务范围。后台恢复和计划任务保持原绑定。

## 执行边界

模型获得结构化浏览器工具。读取页面、HTML、截图和访问授权站点使用当前任务授权。HTML 保留链接与截断信息，可从已观察链接获取下一页地址。后续导航使用新鲜页面 context。

点击、填写和按键可能改变网站数据。单次交互显示实际站点、动作、页面目标和输入内容，敏感输入隐藏；原始参数和摘要在执行详情中查看。重复点击或填写可通过 `browser_authorize_action` 申请 15 分钟的具体操作授权。服务端读取真实元素 HTML，绑定任务目标摘要、浏览器实例、站点、元素摘要、完整输入值摘要及权限版本，并在批准后重新检查目标。目标、输入、配置或任务发生变化后需要重新审阅，恢复时也不能复用与当前目标不符的旧批准。按键操作保留逐项确认。页面按钮名称只作为页面资料。

每个任务拥有独立 Agent Window。会话创建先记录可恢复请求，再创建及确认会话归属。页面读取在前后核验页签和最终 URL，越出范围时阻断正文返回。浏览器动作响应表示动作已执行，业务成功仍需观察页面或核验平台结果。

动作失败记录命令阶段、官方原因及 `effect_state`，仅保存受限诊断字段。只有固定 CLI 明确返回 `effect_state=none` 且要求同步页面时，才允许一次只读等待及重新观察；完整页面地址、元素 HTML、输入及有效授权必须仍匹配，再以新上下文执行。控制权仍由用户持有、目标变化或一次恢复后仍失败时，形成待办，不循环尝试。缺失执行状态或状态未知时不走这条重试路径。

CLI 已确认动作后，立即保存确认摘要，再读取原页面。后续读取失败与动作结果未知分别记录；只允许对同一任务、会话、页签及原页面的真实正文进行回读。回读完成前不再派发浏览器输入，不创建计划，也不能仅凭已有 HTML 或旧来源把任务标为完成。新建或跳转到其他页面不能替代原动作回读。

明确取消会停止该任务的浏览器会话。普通退出先等待 Runtime 真正停止，再只读核对持久操作记录；没有未结浏览器动作时，停止应用自己启动的 driver。存在未结的会话创建、执行中或结果未知动作、已确认但尚待原页回读的动作、数据库不可读或停止结果无法确认时，保留原浏览器现场供核验，不继续执行 Agent 任务。已存在的共享 driver 保持外部归属。

新启动的自有 BrowserSkill 服务使用官方 `--session-idle 30m`，正常空闲期限从最后一次工具活动计算；无浏览器与会话时仍采用官方默认 10 分钟服务空闲回收。用户接管页面可能触发官方空闲保护，因此不是“退出后固定 30 分钟关闭”的计时器。已有服务保留原期限（上游默认会话为 5 分钟），不会为延长期限而重启、轮询保活或恢复已经关闭的网页。此服务仅承载浏览器连接，应用退出后不运行任务协调器或模型。

## 结果未知的公开查询

有限公开查询中的填写或点击没有得到可信回执时，任务保持等待或暂停，保留原始未知记录，不重新执行。任务详情提供 **检查原网页结果**：只读打开原会话的页面观察，展示原目标和非敏感输入，不调用模型、不点击、不填写。需要原站点、浏览器实例、操作定位及当前读取权限仍然可核验；不能以新建网页替代原现场。

用户核对实际结果后，可勾选确认并点击 **保存我的核对结果**。确认使用 120 秒内的观察，保存前再次读取并检查页面及任务版本。页面变化、权限撤销或检查过期时，需要重新核验。保存的是独立的人工确认依据，与平台回执自动验证明确区分；只解除对应动作的等待，其他未结动作仍保持阻断。任务不会自动继续，需单独点击继续；同一已确认动作不能因为重建页面上下文而再次派发。

请尽快核验。原网页过期、关闭或旧记录缺少准确定位时，系统显示具体原因，保留未知记录且不猜测结果或自动重放。该入口仅覆盖已明确批准的有限公开查询，不用于确认审批、付款、报名或其他业务写入成功。

## 周期公开查询授权

普通动作授权仍默认限当前任务 15 分钟。需要每天执行搜索的任务可明确申请 `scope=schedule`、`scheduleAccess=public_query`，审阅实际站点、页面目标、点击或填写动作、精确输入，以及持续用途。该范围只覆盖无需账号的公开查询；网站账号状态记录为未知，不显示账号已经核验。

创建计划时再次展示这些有限动作、执行时刻、时区和范围。确认后把动作写入计划授权及其版本摘要，每次到期为新的任务和浏览器会话派生短授权。执行前重新核对计划仍启用、原授权未撤销、版本、浏览器实例、配置、实际元素和输入一致。新增动作必须再次审阅；读取、导航和由已观察链接翻页继续使用原站点范围。

目标、输入或授权变化会生成持久待办，入口指向对应计划。计划停用、授权撤销和结果未知时停止新派发，未知动作不自动重放。初次执行同样记录未知结果，不能先创建计划来绕过核验。

## 旧技能与配置迁移

0.5.6 中安装的 `browser-skill` 技能资料继续保留。新版本新增受管理 CLI 和连接器设置，既有技能安装无需重复替换。技能资料安装后显示浏览器连接设置入口，连接检查通过后再执行任务。

技能安装、更新、停用和回滚会保存实际根目录清单及递增版本，并向已运行的 KUN 发送刷新请求。Runtime 确认新目录加载后，后续 Turn 使用新清单。旧版本文件保留在安装历史，过期的受管理目录退出当前发现清单。用户自定义目录与旧配置读取路径继续保留。

BrowserSkill 中文匹配词和主机适配说明引导模型使用真实结构化工具。官方技能资料中的 CLI 示例保留原文，RailWise 的主机说明明确对应的受管理执行入口。

旧的 15 分钟动作许可和已有计划保持原范围，文件、回执及执行历史保留。旧计划没有持续动作授权时，读取和导航仍按原授权执行，搜索交互需要明确审阅。源任务仍可执行且目的、其他权限未变时，可以在确认新增动作及计划范围后发布同一计划的新版本，原停用状态不变。源任务已经完成或需要改变其他权限范围时，先在计划详情停用旧计划，再从新的明确任务建立经审阅的计划；系统不自动扩张或替换旧授权，也不宣称完成原计划 ID 的自动扩权。

普通任务的短期动作许可进一步绑定完整页面地址。旧许可及审批记录保留，但缺少页面绑定的旧许可不会用于新执行，需要在实际页面重新审阅；原因是同一站点不同页面可能具有完全相同的按钮 HTML，不能据此复用另一个页面的批准。已有周期公开查询许可原本包含页面地址，继续按原版本与范围核验。

旧 `gui_schedule` MCP（含 `claw_schedule` 兼容名）的配置、凭据引用、已有计划和执行历史继续保留，GUI、IM 与非 Task 兼容入口仍可使用。带任务 ExecutionGrant 的执行范围内，旧桥八个读写工具退出模型目录，旧工具重放及 MCP 搜索、直接调用均拒绝并引导使用 `schedule_task`、`list_schedules`。原因是旧桥可独立指定正文、工作区和时间，无法承载当前任务的持续权限及读回验收。其他 MCP 按原授权使用。用户无需重装连接器；当前任务通过原生工具建立计划，既有兼容计划仍从原管理入口调整，不自动转换或扩大权限。

时间解析不再把 URL 的端口、路径和查询参数当成时刻。既有计划及运行历史保留，升级不会猜测并重写用户原时刻；若曾用含端口的 URL 建立每日任务，请在计划详情核对执行时间并按实际要求修改。

## 本轮验证边界

已通过生产 ManagedBrowserSkillService 的真实 macOS arm64 CLI 安装、版本检查、独立 foreground daemon 启停和协议 1.7 检查。首次 Node 网络下载失败后，使用官方来源正常 TLS 下载同一固定归档，再经过生产下载器的大小和摘要验证。此记录验证安装与执行依赖，国内镜像的首次下载单独验收。

自动回归覆盖缺失连接器时零 Turn、任务原始请求持久化、同一 Runtime 技能热更新、中文激活、旧版本目录退出、站点范围、实例变化、有限交互授权、过期和暂停、未知会话创建恢复及单任务会话归属。

真实扩展连接和安装包内端到端采集结果由本轮候选包验收记录补充。仅 CLI 和 daemon 检查通过时，界面继续显示等待扩展连接。
