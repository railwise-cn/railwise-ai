# 显式重试的授权、计划与历史成果兼容

旧任务及其失败记录、执行时间、费用、审批、文件和工具回执全部保留。只有用户主动选择“重试”才创建同一可见业务任务下的新执行分支；它继续使用原 Root 账本，不能获得被清零的预算。

旧版本的重试只复制成果元数据，并遗漏浏览器任务范围。新执行不再把复制的历史文件显示为自己的有效写入成果。仍可按原任务的历史成果入口阅读；经服务器核验真实重试控制记录、原写入回执和当前文件哈希后，执行器也可以使用 `read_artifact` 的 `source_task_id` 只读参数参考旧草稿。旧文件不会删除或移动，新执行必须发布自己的修订文件并重新通过所需验收。历史来源记录不自动成为新执行的来源核验证据。

只有原目的、工作区、站点、浏览器身份及计划要求均仍有效的持续计划授权，才可由显式重试为新执行派生范围。新的 Turn 使用新的不可变 Grant；旧 Grant、浏览器会话和单次点击或输入授权均不继承。已撤销、取消、到期、配置发生变化或缺少可信链的授权需要通过现有权限入口重新检查。原任务和重试链中存在未知结果或已派发的真实外部写操作时，原核验和防重放门禁继续生效。

内置上下文读取和本地进度清单与外部平台写入分开判断。内置定时计划还必须通过其原 Root 计划及当前授权的只读核验；同名 MCP 工具或模型自述不能获得本地工具豁免。每日计划沿同一业务 Root 复用，不能因执行分支变化创建重复计划。

无需重装 Skill、删除历史任务或重填现有凭据。对于仍有真实权限、网络或业务证据缺口的任务，重试继续显示具体阻断；历史草稿可读不代表最终业务验收已完成。
