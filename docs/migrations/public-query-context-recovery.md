# 公开查询上下文恢复

旧版本的有限公开查询遇到浏览器会话过期时，原操作会保留“结果未知”。本次增加“准备重新检索”和独立的“继续重新检索”，当前只覆盖已有持续计划及 schedule-duration 授权的查询。一次性 task-duration 授权不延续到新执行，需正式重新审阅范围。本次入口只适用于服务端能逐项核对原生公开查询目标、授权、会话、任务及计划身份的记录。准备仅保存审计与任务版本，不启动模型或网页；继续使用原任务的标准重试关系、共享预算和原交付要求，生成短期、范围收窄的新执行授权。

旧 Host、派发记录、计划锁及账本不删除、不改成成功或“未执行”。旧上下文、会话、目标引用和执行凭证不再派发。旧注意卡会明确记为“上下文已封存，结果仍未知”，新执行仍需重新观察、授权具体公开查询目标并读取正文。原计划的内容、版本、持续授权和时间设置保持不变；只有同计划、版本、范围及浏览器身份的可信恢复链可供后续到期执行使用。

原网页结果无法核验且存在业务提交、账号操作、主机命令、任意 MCP 写入、未列举未知操作、授权撤销或身份变化时，不提供此例外，仍需处理原阻断。新受限执行也不包含这些写入能力。若准备或启动过程中断，可用同一操作重试；已经生成但尚无 Turn 的重试任务只保留为待继续，不自动启动或重放。

无需重装技能、删除历史任务或重新填写凭据。此功能不自动补足报告来源，不等同于事实验收：网页成果仍需独立核验正文来源、文件与对应哈希。

本次不将先前原生浏览器派发的未知原因视为已修复，也不将无法核验解释成“未执行”。供应商或浏览器派发故障仍需独立诊断；这里只建立可审计的新受限执行通道。
