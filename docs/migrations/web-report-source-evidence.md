# 网页报告来源验收迁移

原有 HTML 成果、Skill、插件、MCP 配置、凭据引用、工作区与操作回执全部保留。文件的 `validation=valid` 继续表示文件存在、可读且指纹有效，不代表报告里的信息已经核验。

需要网页来源的 HTML 任务新增逐文件 `sourceEvidenceStatus`：没有来源证明的旧成果是可阅读、可预览的草稿；`verified` 必须关联精确文件哈希、成功写入回执、当前任务要求与可信来源读取回执。`sourceEvidenceReceiptId` 指明证明记录。新正式成果不会替其他历史草稿背书，历史文件不会被删除或强制批量改写。

成功的成果写入回执及会话结果落盘后，任务会登记实际文件的新指纹，模型仍在执行时也能预览草稿。同一文件继续更新时沿用原成果身份，旧来源证明不会自动应用到新内容。暂停、失租、失败或结果未知的执行不能登记新的成果信息，也不能据此恢复任务；预览继续检查文件与回执的精确版本。

继续原任务即可补齐来源，无需重新安装或删除历史。Worker 从实际页面读取结果链接与完整正文，逐条记录标题、预算、日期、截止或有效状态及资格的原文依据，再更新同一成果。需要用户接管的只有真实登录、权限或不可恢复访问阻断；缺失正文由 Worker 继续核查。有效且同任务目的的跨 Turn 来源可以复用，重新绑定浏览器不会无条件丢弃已核实资料，也不会授权重放旧操作。

`verify_web_artifact` 只读取当前任务自己的已保存 HTML 与已有可信来源，不联网，不执行页面，不提升工作区权限。正式数据区使用 `data-evidence-report`；每条 `tr/article/section` 标记 `id`、`data-evidence-item` 与分类；值使用 `data-evidence-field`；正文链接使用 `data-evidence-source`。未读字段使用 `data-evidence-unverified` 并显示“待核验”。未声明条目、字段或无据数据行不能借一条真实来源通过。

每个必需平台都应有相关正文或真实查询零结果证据。招标机会、采购意向和历史合同分别列出；已过截止日期不能列作当前机会。预算等未披露字段可以保留待核验，不能宣称所有条款均已核验。核验范围是声明的结构化正式数据区，不是任意叙述文字的全语义真实性。

普通聊天、代码交付和没有网页来源要求的文件任务保持原流程。尚未核验的报告仍可查看，任务保持未完成并携带具体修复指引。新完成结果逐文件列出路径、哈希和来源证明。
