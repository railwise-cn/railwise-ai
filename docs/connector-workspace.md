# 技能与连接器工作台

## 用户入口

侧栏的“技能与连接器”按“技能 → 插件 → 连接器”排列三个独立页签，普通打开时默认进入“技能”。任务中的连接器入口直接定位对应详情。旧 `plugins` 路由继续兼容。

| 页签 | 内容 | 主要操作 |
| --- | --- | --- |
| 技能 | 可安装的技能包、可选工程技能和现有本地技能索引 | 发现技能、查看使用说明、审阅安装、按来源和健康状态查找 |
| 插件 | 扩展包与工程办公精选工具 | 查看来源、审阅权限、安装、更新、回滚 |
| 连接器 | 飞书/Lark、钉钉、GitHub、高德、Zotero及实际目录中的连接服务 | 查看能力和示例、配置、授权、检查状态、启用或停用 |

连接器与技能分别搜索和展示，不再把外部账号授权混在技能文件列表中。连接器的详情页说明当前实现支持的操作和写入确认边界；示例用于说明能力，不会点击后自行执行真实业务。

## 连接流程

飞书/Lark 和钉钉使用各自独立的官方连接流程，不互相替代。用户无需在聊天中提供账号或密钥。

- **飞书/Lark**：点击“连接”后检查受管理 CLI，缺失时安装官方依赖，再进入官方应用配置和账号授权。应用配置与用户登录是不同步骤；扫码和权限同意由用户在官方页面完成。详情也可以只读打开，不自动启动授权。
- **钉钉**：使用官方 DWS CLI 的连接和设备授权入口。原 OpenAPI 企业应用配置保留在详情的“高级企业应用配置（兼容）”中，继续服务已有配置。
- **GitHub** 在专属详情中创建并填写个人访问令牌（PAT），默认使用官方只读 MCP 服务。保存并检查完成后，再明确启用任务工具。组织审批、SSO、仓库和令牌权限共同决定业务访问范围。高级 MCP 设置保留已有 OAuth 配置。[GitHub 连接说明](github-connector.md)
- **高德地图** 在配置卡中填写高德 Web 服务 Key，再检查官方 HTTP MCP 连接。可用工具按已核对的只读清单筛选。
- **Zotero** 安装固定版本的社区 MCP 包，在本机打开 Zotero 并启用本地 API，再检查连接和选择任务可用范围。预置配置仅启用经核对的本地只读工具。
- **其他目录连接器** 沿用各自真实的安装、OAuth、配置与权限审阅入口，连接状态由相应适配器核验。

已有显式停用状态会保留。钉钉详情提供独立的启用/停用操作；启用只更新连接器状态，不开始登录或执行等待任务。连接成功不等于批准业务写入。完成待办、同意或拒绝审批仍需明确目标和相应任务授权，并产生可核验的操作回执。连接器页面不会自动处理真实待办、审批或消息。

聊天阻断卡片和任务详情中的“配置连接器”直接打开对应平台详情，不再让用户在通用设置中查找。此跳转仅定位配置页面；不会自动安装、启动授权或恢复任务。用户连接成功后，仍通过原任务的“重新检查并继续原任务”触发能力复核，保留原任务及等待事项的归属。

## 状态与离线行为

飞书和钉钉的设置入口来自已实现的本机适配器，即使远端目录不可用也仍可打开。其余连接器来自实际目录或保留的已验证缓存，不填充不存在的“可用”服务。

页面区分依赖未安装、需要登录、已登录待核验能力范围、需要配置、检查失败、已停用以及已核验可用。可用状态必须来自运行时能力和实际身份诊断，不能仅凭包已安装、`credentialRef` 存在或退出码为零判断。

高德、Zotero 和 GitHub 的实际工具发现检查通过后，列表显示“连接检查通过”、可用工具数量和检查时间。关闭详情或重启应用后可查看这次记录。修改连接地址、凭据或工具范围，以及停用连接后，需要重新检查。业务操作的实际结果与验证证据在对应任务详情中查看。

钉钉官方 DWS 的本机身份诊断读取保存的账号和凭据有效期，页面据此显示“已保存钉钉登录信息”。用户可点击“重新授权 / 切换账号”取得新的官方设备授权二维码，也可使用“复制授权链接”和“打开本机钉钉”。“测试待办读取”通过正式 Provider 和受限 ExecutionGrant 查询第一页、最多一条未完成待办，界面仅显示条数与错误分类。审批权限和业务写入按相应操作单独核验。

官方扫码页面完成与本机连接完成是两个独立事实。钉钉使用设备授权，由本次受管理进程向官方服务等待结果，不依赖 Chrome 跳回本机端口。即使进程在显示链接前正常退出，也必须核验本次官方结果及精确账号；不能只凭退出码显示已连接。飞书首次应用配置同样核验本次新增的命名配置，再进入账号授权。取消、超时或新流程取代后，旧的异步核验不得触发后续登录或更新为成功。

### 当前目录的覆盖规则

工作台合并内置及用户配置的目录、原生连接入口、本机安装记录和 Runtime 能力。内置条目定义在 `src/main/services/official-marketplace-catalog.ts`。目录条目的 `productType` 决定分类，`availability` 与安装模式决定可执行入口，账号和任务权限由运行时另行检查。用户可以分别看到可安装、需要配置、已安装和当前不可用状态。

| 范围 | 条目与当前边界 |
| --- | --- |
| 原生办公连接 | 飞书/Lark 使用受管理 `lark-cli`，钉钉使用官方 DWS。两者均有独立的配置、授权、身份诊断和任务权限检查 |
| GitHub 远端连接 | `github-mcp` 使用专属 PAT 配置和官方 MCP 检测。新连接默认只读，写能力由用户明确选择，并继续受任务授权约束 |
| 高德地图 | `amap-maps` 使用高德官方 HTTP MCP 和 Web 服务 Key。连接通过后提供已核对的只读工具 |
| Zotero 本机文献 | `zotero-mcp` 使用固定上游 wheel、本机 API 和隔离配置。安装保留 `MIT AND AGPL-3.0-or-later` 声明，预置能力限定为文献库只读查询 |
| 可选工程技能 | 资料盘点与来源索引、监测质检与图表、工程文档差异审阅、会议纪要与待办，由用户选择安装 |
| 工程办公精选 | MarkItDown、Docling、OfficeCLI、AntV 图表及 Playwright 集中展示已有能力，继续使用各自安装、配置和任务权限入口 |
| AutoCAD 社区技能 | `autocad-dwg-redraw` 与 `autocad-image-redraw` 由用户点击“从上游安装”，按固定 commit 和归档 SHA-256 下载到本机。上游尚未声明许可证，元数据保留 `license: null`。DWG 执行需要用户许可的 Windows AutoCAD COM，图片路径的跨平台 DXF 流程仍需实际环境核验 |
| 数据库及其他本地工具 | `dbhub`、`redis-mcp`、`mongodb-mcp` 等按目标配置地址、凭据和范围。文件、浏览器、记忆、图表和检索工具按实际依赖和任务权限启用 |
| 应用知识库 | `railwise-kb` 由应用管理，运行时核验可访问资料和项目范围 |
| 待接入的远端来源 | `notion-mcp`、`linear-mcp` 继续标记为 `unavailable / oauth-discovery-pending`，保留来源与现有配置入口 |

AutoCAD 两项来自 `pengxiaoan` 社区仓库。本轮将之前仅可打开来源的条目改为用户主动的 `upstream-only` 安装，复用来源与权限审阅、内容摘要、完整文件暂存和原子安装。先前的未知许可证阻断来自目录策略，本次将用户上游导入与公司再分发分别处理。公司镜像及应用资源中排除这两项源码，安装仅从固定上游下载并保留原始文件和存在的声明，许可证状态保持未知。已有本地 Skill、旧配置及安装记录保留原状，用户可在市场选择安装或继续使用原有文件。安装可在支持的平台导入技能资料，实际脚本执行仍需具备相应许可、依赖、选定资料与输出授权。[固定版本源码](https://github.com/pengxiaoan/autocad-dwg-redraw-skill/tree/ed182ec5966caaaf1d82d6ad4015435a27a8a909)

### 固定依赖与国内下载

uv、CPython、Lark CLI、OfficeCLI 的版本、官方来源、许可证、大小和 SHA-256 统一记录在受管理依赖清单。安装优先访问 RailWise 公司下载入口，再按相同摘要核验固定官方来源。Lark 和 OfficeCLI 的配套技能使用同版本固定源码，已有技能目录保留供审阅。钉钉 DWS 沿用已核验的官方国内源和摘要校验。[受管理依赖分发](managed-dependencies.md)

公司域名冷缓存验证已覆盖上述运行环境、Lark、OfficeCLI及其配套技能。Zotero 已完成固定包安装与实际 MCP 初始化、工具发现，用户本机文献库读取还需要开启本地 API。高德需要有效 Key，外部平台业务操作需要相应账号、scope及明确任务范围。

读取状态失败会清除页面中过期的成功状态，显示待核验；不会因此删除、禁用或重写现有安装、凭据或 MCP 配置。连接状态读取本机诊断与运行时快照，外部授权由明确的“连接”操作启动。

## 兼容迁移说明

| 旧项 | 新状态 | 原因 | 数据保留与用户操作 |
| --- | --- | --- | --- |
| 侧栏“插件”入口 | 显示为“技能与连接器”，原路由保留，默认技能页签 | 按用户目标区分技能使用、账号连接和包管理 | 不迁移文件；原插件管理在“插件”页签继续使用 |
| 混合目录中的连接器 | 集中到“连接器”，保留原详情和安装/权限交易 | 避免把已安装与已授权混为一谈 | 已安装包、来源和 MCP 记录保留；在连接器详情继续管理 |
| 本地技能与技能包 | 集中到“技能”，保留原来源和健康筛选 | 将技能文件与外部账号授权分开 | 不移动、删除或覆盖 Skill；原目录、索引及用户内容继续保留 |
| GitHub 旧 OAuth 入口 | 专属 PAT 配置作为新连接入口，高级 MCP 继续管理旧 OAuth | 为已有官方 PAT 认证提供直接配置与检测路径 | 原端点、OAuth 字段、凭据引用和工具规则保留，用户明确保存或切换后修改对应连接 |
| 已保存的 MCP 连接配置 | 新增绑定配置版本的连接检查记录 | 让实际检查结果在列表、详情和重启后保持一致 | 原服务、凭据引用和启用选择保留；旧配置点击“检查连接”后生成新记录 |
| 原钉钉 HTTP/OpenAPI 应用配置 | 折叠为高级兼容入口；官方 DWS 设备授权作为主连接路径 | 新用户可以通过官方授权连接，已有企业应用继续兼容 | 不删除原应用配置或凭据引用；需要原方式时展开高级配置 |

飞书卡片合并展示官方登录流程后，原 `lark-openapi-mcp` 包仍可从飞书详情的“高级原包管理”打开原包详情，查看来源、权限、已安装版本、更新诊断和原有可用管理操作。此入口只切换展示，不改写安装记录或 MCP 配置。

## 同类产品参考与证据边界

2026-11-10 在 WorkBuddy 5.7.6 的实际界面观察到：同一入口提供独立的专家、技能、连接器页签；连接器卡片有能力说明、使用示例和“连接”；点击飞书连接后由应用开始安装依赖并展示进度，无需先填写账号。

该次观察尚未取得扫码授权成功或真实业务执行证据，也没有检查其内部实现。RailWise 吸收的是分类、连接引导和状态反馈的交互方式。WorkBuddy 的目录数量、能力描述和界面截图不作为 RailWise 已支持范围、协议正确性或账号验收通过的证据。

RailWise 的自动化 DOM 回归验证页签分离、原数据入口保留、离线可见、授权状态不误报、明确点击后才启动连接，以及详情关闭和导航。精确包视觉、官方扫码和真实账户操作仍按本轮验收记录分别验证。
