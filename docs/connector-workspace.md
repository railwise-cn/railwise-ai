# 技能与连接器工作台

## 用户入口

侧栏的“技能与连接器”集中提供三个独立页签，首次打开默认进入“连接器”。旧 `plugins` 路由继续兼容。

| 页签 | 内容 | 主要操作 |
| --- | --- | --- |
| 连接器 | 飞书/Lark、钉钉，以及实际目录中声明为连接器的服务 | 查看能力和示例、连接、官方授权、检查状态、管理连接 |
| 技能 | 可安装的技能包和现有本地技能索引 | 发现技能、查看使用说明、审阅安装、按来源和健康状态查找 |
| 插件 | 其他扩展包的安装、更新和权限管理 | 查看来源、审阅权限、安装、更新、回滚 |

连接器与技能分别搜索和展示，不再把外部账号授权混在技能文件列表中。连接器的详情页说明当前实现支持的操作和写入确认边界；示例用于说明能力，不会点击后自行执行真实业务。

## 连接流程

飞书/Lark 和钉钉使用各自独立的官方连接流程，不互相替代。用户无需在聊天中提供账号或密钥。

- **飞书/Lark**：点击“连接”后检查受管理 CLI，缺失时安装官方依赖，再进入官方应用配置和账号授权。应用配置与用户登录是不同步骤；扫码和权限同意由用户在官方页面完成。详情也可以只读打开，不自动启动授权。
- **钉钉**：使用官方 DWS CLI 的连接和设备授权入口。原 OpenAPI 企业应用配置保留在详情的“高级企业应用配置（兼容）”中，继续服务已有配置。
- **其他目录连接器**：只展示实际目录中的条目，沿用对应包的安装、OAuth、配置与权限审阅入口。不存在真实授权适配的条目不能显示为已授权。

已有显式停用状态会保留。钉钉详情提供独立的启用/停用操作；启用只更新连接器状态，不开始登录或执行等待任务。连接成功不等于批准业务写入。完成待办、同意或拒绝审批仍需明确目标和相应任务授权，并产生可核验的操作回执。连接器页面不会自动处理真实待办、审批或消息。

聊天阻断卡片和任务详情中的“配置连接器”直接打开对应平台详情，不再让用户在通用设置中查找。此跳转仅定位配置页面；不会自动安装、启动授权或恢复任务。用户连接成功后，仍通过原任务的“重新检查并继续原任务”触发能力复核，保留原任务及等待事项的归属。

## 状态与离线行为

飞书和钉钉的设置入口来自已实现的本机适配器，即使远端目录不可用也仍可打开。其余连接器来自实际目录或保留的已验证缓存，不填充不存在的“可用”服务。

页面区分依赖未安装、需要登录、已登录待核验能力范围、需要配置、检查失败、已停用以及已核验可用。可用状态必须来自运行时能力和实际身份诊断，不能仅凭包已安装、`credentialRef` 存在或退出码为零判断。

钉钉官方 DWS 的本机身份诊断只能证明当前账号/token 状态，不提供业务 Scope 验证结果，因此页面显示“账号已连接 · 平台权限执行时核验”，不宣称待办或审批权限已实测通过。

### 内置目录的实际覆盖范围（2026-11-10）

`src/main/services/official-marketplace-catalog.ts` 当前生成 40 个包，其中 18 个标记为 `connector`。这一分类包含本地文件、浏览器、记忆、图表和数据库工具，不等同于 18 个可扫码的外部办公平台。目录中的 `available` 表示允许安装或配置，不证明用户账号、网络或业务权限已核验。

| 范围 | 条目与当前边界 |
| --- | --- |
| 预设远端 OAuth 入口 | `github-mcp` 声明 OAuth discovery ready，复用通用 MCP OAuth、PKCE 和本机回调。是否能完成取决于远端 discovery/client registration、网络和用户授权；尚不能仅凭目录声明认定账号连接成功。 |
| 原生官方登录 | 飞书原生入口复用 `lark-cli` 和目录中的 `lark-openapi-mcp`；钉钉原生入口使用本轮 DWS 适配，尚不是上述 18 个目录条目之一。二者都需用户在官方页面完成授权并核验权限。 |
| 数据库连接 | `dbhub`、`redis-mcp`、`mongodb-mcp` 只有受管工具安装与 `tool-managed` 标记，仍需按目标数据库配置连接地址、凭据和访问范围；本轮没有为它们增加扫码或专门配置向导。 |
| 本机或公共资源工具 | `playwright-mcp`、`context7-mcp`、`antv-chart-mcp`、`filesystem-mcp`、`memory-mcp`、`sequential-thinking-mcp`、`git-mcp`、`fetch-mcp`、`time-mcp`、`docling-mcp` 共 10 项声明无需账号 OAuth，仍需安装依赖并满足工作区、浏览器或网络权限。 |
| 应用管理的知识库 | `railwise-kb` 是应用管理的知识库连接，不是扫码登录平台；实际可访问性仍须运行时验证。 |
| 尚不可用的预置条目 | `notion-mcp`、`linear-mcp` 明确为 `unavailable / oauth-discovery-pending`；不将它们作为已接入能力。内置目录没有单独标记为 `preview` 的连接器。 |

因此，本轮统一界面和飞书/钉钉连接引导不代表完成 WorkBuddy 中其他平台的接入。未适配的平台继续通过实际目录状态、MCP 配置和明确能力边界展示，不填充虚构服务或承诺登录即用。

读取状态失败会清除页面中过期的成功状态，显示待核验；不会因此删除、禁用或重写现有安装、凭据或 MCP 配置。普通打开目录只读取本机诊断与运行时快照，外部授权仅由明确的“连接”操作启动。

## 兼容迁移说明

| 旧项 | 新状态 | 原因 | 数据保留与用户操作 |
| --- | --- | --- | --- |
| 侧栏“插件”入口 | 显示为“技能与连接器”，原路由保留；默认连接器页签 | 按用户目标区分技能使用、账号连接和包管理 | 不迁移文件；原插件管理在“插件”页签继续使用 |
| 混合目录中的连接器 | 集中到“连接器”，保留原详情和安装/权限交易 | 避免把已安装与已授权混为一谈 | 已安装包、来源和 MCP 记录保留；在连接器详情继续管理 |
| 本地技能与技能包 | 集中到“技能”，保留原来源和健康筛选 | 将技能文件与外部账号授权分开 | 不移动、删除或覆盖 Skill；原目录、索引及用户内容继续保留 |
| 原钉钉 HTTP/OpenAPI 应用配置 | 折叠为高级兼容入口；官方 DWS 设备授权作为主连接路径 | 新用户可以通过官方授权连接，已有企业应用继续兼容 | 不删除原应用配置或凭据引用；需要原方式时展开高级配置 |

## 同类产品参考与证据边界

2026-11-10 在 WorkBuddy 5.7.6 的实际界面观察到：同一入口提供独立的专家、技能、连接器页签；连接器卡片有能力说明、使用示例和“连接”；点击飞书连接后由应用开始安装依赖并展示进度，无需先填写账号。

该次观察尚未取得扫码授权成功或真实业务执行证据，也没有检查其内部实现。RailWise 吸收的是分类、连接引导和状态反馈的交互方式。WorkBuddy 的目录数量、能力描述和界面截图不作为 RailWise 已支持范围、协议正确性或账号验收通过的证据。

RailWise 的自动化 DOM 回归验证页签分离、原数据入口保留、离线可见、授权状态不误报、明确点击后才启动连接，以及详情关闭和导航。精确包视觉、官方扫码和真实账户操作仍按本轮验收记录分别验证。
