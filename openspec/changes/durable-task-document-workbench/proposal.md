## Why

The existing task workbench has persistent building blocks without a complete production execution path. Supplements can be acknowledged too early, unrelated requests can cancel work, and public release artifacts still use the retired WorkWise brand.

## What Changes

- Preserve stable user tasks while making execution sessions and attempts internal, durable identities.
- Route status, supplement, new-task, and ordinary chat commands before allocating a model turn.
- Finish checkpoint-confirmed input delivery, execution fencing, operation reconciliation, process recovery, shared capacity and root budgets.
- Connect source inboxes, subscriptions, scoped context, handoffs, task streams, and document review to the production runtime.
- Generate branded installers, feeds, release records, and website downloads from one publication manifest while retaining legacy identities and URLs.
- Prove the changes with production-assembly fault tests, three synthetic document scenarios, actual-model samples, and exact-package verification.

## Capabilities

### New Capabilities

- `task-workbench`: Reliable continuous tasks, local attention, reviewable document delivery, and compatible branded publication.

### Modified Capabilities

None. Existing IPC, configuration readers, application identity, and historical data remain compatible.

## Impact

KUN task/Flow SQLite migrations, coordinator and tool execution, renderer task state, main/preload SSE and document IPC, packaging scripts, GitHub workflows, and website manifests. No additional runtime, system daemon, remote embedding service, or new external listener is introduced.
